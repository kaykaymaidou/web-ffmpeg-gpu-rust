# RFC 0001: 网页端客户端 GPU 视频转码与压缩引擎 (Client-side GPU Transcoder)

- **状态**: Accepted (已访谈对齐通过)
- **提出时间**: 2026-09-08
- **责任模块**: `crates/core` (Rust Muxer & Demuxer), `packages/core` (WebCodecs & WebGPU), `apps/playground` (可视化看板)

---

## 1. 业务背景与问题痛点

现代手机（iPhone / Android 旗舰）实拍视频码率动辄 50Mbps ~ 100Mbps（4K 60fps），单个短视频体积常达数百兆至数吉字节，极不适宜直接进行网页传输或社交分享。

以往在浏览器端进行转码通常依赖 `ffmpeg.wasm`（纯 CPU 软转码）：
- **耗时漫长**：1 分钟的 4K 视频需要 5~10 分钟才能转完；
- **风扇狂转**：CPU 持续 100% 满载，网页极易卡顿、无响应甚至崩溃；
- **发灰发白**：缺乏 iPhone HDR 色调映射，转码后色彩严重褪色失真；
- **播放卡死**：生成的 MP4 默认未开启 `faststart`，必须等到全文件下载完成才能开始播放。

## 2. 目标规格与核心决策 (Aligned Decisions)

经用户深度访谈，确立以下关键架构决策：

### 2.1 智能预设档位 (Presets)
| 预设名称 | 目标分辨率 | 目标码率 (Bitrate) | 适用场景 |
| :--- | :--- | :--- | :--- |
| **社交分享 (Social)** | 1280x720 (720p) | 2.5 Mbps | 微信/飞书/小红书秒发，极小体积 |
| **高清网盘 (HD Web)** | 1920x1080 (1080p) | 5.0 Mbps | 兼顾清晰度与流媒体加载速度 |
| **原画瘦身 (Original Slim)** | 保持原视频宽高 | 8.0 Mbps | 仅削减过剩高码率，完全保留画面解析度 |

### 2.2 音频原样直通复制 (Audio Passthrough / Copy)
- 提取源容器中的 AAC 音频流原始 Packet，绕过任何音频重编码，直接作为第二轨道封进目标 MP4；
- **收益**：音质零损耗，音频处理耗时为零，支持一键无声静音选项。

### 2.3 强制开启 `faststart` (Web 边下边播优化)
- 纯 Rust 封装器在组装 MP4 时，将 `moov` 索引头置于 `mdat` 数据块之前；
- 导出的 MP4 文件在任何网盘或静态网页服务器上均可做到**秒开预览**，无需等待全量下载。

### 2.4 真实边缘场景加固 (Edge Cases)
1. **旋转角度自适应 (Orientation Correction)**：
   - 提取 `tkhd` 矩阵，自动检测手机竖屏拍摄角度（90°/180°/270°），在 WebGPU 视口中自动矫正为物理正向。
2. **HDR 色调映射 (Tone Mapping)**：
   - 针对 iPhone 10-bit / HLG / PQ 视频，在 WebGPU WGSL 着色器中加入 Reinhard / ACES 色调映射曲线，杜绝画面发白。

### 2.5 背压与显存防护机制 (Backpressure & VRAM Safety)
- **显存帧水位线限制**：WebCodecs 硬解全速解时，严格限制内存/显存中同时挂起的 `VideoFrame` 实例数量（建议保持 8~16 帧低水位线）。
- **编码器背压控速**：当 `VideoEncoder.encodeQueueSize > 8` 时，主动暂停解码消费，等待编码器 `dequeue` 事件触发后再继续解码，彻底杜绝 4K/长视频导致 GPU 显存爆满与显卡驱动重置 (TDR)。

### 2.6 异常码流宽容容错 (Fault Tolerance & Graceful Degradation)
- **宽容容错模式**：遇到损坏的 NAL 单元或被截断的切片时，跳过该异常块并记录格式诊断警告，不 panic 崩溃。
- **首包非 IDR 脏帧自愈**：如果截取的视频切片开头是非关键帧（B/P 帧），自动丢弃直到遇到第一个合法的 IDR 关键帧，防止输出开头绿屏或花屏。

### 2.7 深度可视化交互与测试敲打体系 (Show-Me & Test Matrix)
Playground 与调试界面集成三大能力：
1. **实时性能看板**：实时显示转码倍速 (如 12.8x-realtime)、瞬时 FPS、输出压缩率 (如节省 86%)、预计剩余时间；
2. **底层码流剖析器**：可视化展示 Rust 解封装出的 ISOBMFF Box 树 (ftyp/moov/trak/stsd/mdat)、H.264 SPS/PPS 参数分析、NAL 类型统计；
3. **原画与输出画质双联对比视窗**：左右分屏或同屏画中画同步拖拽播放，直观比对原视频与转码后视频的画质、色彩与滤镜效果；
4. **绑定用例库**：所有改动对照 `tests/cases/README.md` 进行压力敲打与回归校验。

## 3. 系统数据通路架构 (Pipeline Dataflow)

```
┌─────────────────────────────────────────────────────────────┐
│                    用户手机实拍原始视频文件                     │
│                    (高码率 4K/1080p MP4/MOV)                │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│             纯 Rust 解封装器 (crates/core/demuxer)            │
│   - 提取视频轨道参数 (SPS/PPS, NAL 样本流)                     │
│   - 提取音频轨道数据 (AAC Packets，备用直通)                   │
└──────────────┬──────────────────────────────┬───────────────┘
               │ (视频流)                      │ (音频流直通)
               ▼                              │
┌──────────────────────────────┐              │
│    WebCodecs VideoDecoder    │              │
│       (显卡专用芯片硬解)       │              │
└──────────────┬───────────────┘              │
               │ (VideoFrame 显存零拷贝)       │
               ▼                              │
┌──────────────────────────────┐              │
│     WebGPU WGSL 处理管线     │              │
│  - 分辨率缩放 (720p/1080p)   │              │
│  - 竖屏旋转矩阵矫正          │              │
│  - HDR 色调映射 (Tone Mapping)│              │
└──────────────┬───────────────┘              │
               │ (Render Canvas / Texture)    │
               ▼                              │
┌──────────────────────────────┐              │
│    WebCodecs VideoEncoder    │              │
│   (显卡专用芯片高速硬件压缩)   │              │
│    目标码率: 2.5M / 5M / 8M  │              │
└──────────────┬───────────────┘              │
               │ (编码产出 EncodedVideoChunk) │
               ▼                              │
┌─────────────────────────────────────────────┴───────────────┐
│              纯 Rust 封装复用器 (crates/core/muxer)            │
│    - 将编码后的视频 Chunk 组装为标准 AVCC 格式                 │
│    - 将音频直通 Packet 组装为 MP4 第二轨道                   │
│    - 组装 moov 索引头置于文件最前端 (Faststart 优化)           │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                  产出最终极速压缩完成的 MP4 文件                │
│       (体积节省 80%~92%, 实时转码倍速 150+ FPS, 支持一键下载)   │
└─────────────────────────────────────────────────────────────┘
```

## 4. 实施阶段拆解 (Implementation Steps)

- **Step 1**: 在 `crates/core/src/muxer/mp4.rs` 中落地带 `faststart` 的纯 Rust MP4 封装器与音频直通支持；
- **Step 2**: 在 `packages/core/src/encoder/hardware-encoder.ts` 中封装 WebCodecs 硬件编码器；
- **Step 3**: 在 `packages/core/src/pipeline/transcoder.ts` 中串联端到端转码流程，支持预设档位与进度回调；
- **Step 4**: 在 `apps/playground` 中升级可视化操作面板（进度条、FPS/倍速监控、体积压缩比与下载按钮）；
- **Step 5**: 在 `tests/e2e/transcoding-pipeline.spec.ts` 中编写 Playwright 端到端转码校验用例。
