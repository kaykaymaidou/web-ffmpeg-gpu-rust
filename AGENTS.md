# Web-FFmpeg-GPU Architecture & Engineering Invariants (Monorepo Master Charter)

This project builds a next-generation, high-performance multimedia engine powered by a **pure Rust cross-platform core** and accelerated by platform-native hardware:
- **Web**: **WebCodecs** (GPU ASIC hardware decode/encode) + **WebGPU** (zero-copy WGSL shader filters/composition) + **crates/core WASM**.
- **Desktop & Native**: **crates/native** (NVENC/QSV/VideoToolbox FFI + DirectX/Vulkan) + **apps/desktop** (Tauri).
- **Service**: **apps/windows-service** (Windows 7x24h background streaming/transcoding service).
- **AI Autopilot**: **packages/agent** (Decoupled DeepSeek Harness `dsh` paradigm).

---

## 1. Monorepo Master Architecture & Boundary Rules

```
crates/core (Pure Rust Core: Zero-IO, Zero-Panic, Dual WASM & Native compilation)
   │
   ├──> packages/core (Web SDK: WebCodecs + WebGPU + WASM) ──> apps/playground (Web UI)
   │
   ├──> crates/native (Desktop SDK: OS Hardware Codecs + C-ABI)
   │        │
   │        ├──> apps/desktop (Tauri Desktop App)
   │        └──> apps/windows-service (Windows 7x24h Background Service)
   │
   └──> packages/agent (AI Autopilot Engine) ──> Telemetry & Autonomous Self-Healing
```

- **Dependency Direction**: Outer layers depend on inner layers; inner layers NEVER depend on outer layers.
- **`crates/core`** is strictly platform-agnostic: NO browser dependencies, NO Node.js dependencies, NO OS-specific I/O.

---

## 2. Pure Rust Core Boundary Constraints (`crates/core`)
- **Zero OS I/O Invariant**: `crates/core` MUST NOT execute direct filesystem reads/writes or socket network calls. It only transforms byte streams (`&[u8] -> Result<Vec<u8>, MediaError>`). All I/O is provided by outer layers (Web fetch/WebSocket, Tokio/IOCP).
- **Dual-Compilation Invariant**: `crates/core` must compile cleanly to both `wasm32-unknown-unknown` and native targets (`x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`).
- **Zero Panic Invariant**: Parsing of container formats (MP4, MKV, WebM, FLV, TS) and bitstreams (H.264 Annex B / AVCC, H.265 HVCC, AV1 OBUs) MUST safely handle malformed inputs, truncated NALs, and 32-zero Exp-Golomb traps with typed `Result<T, MediaError>`, never `panic!` or unhandled `.unwrap()`.

---

## 3. Web Platform Native Efficiency Invariant (Zero Format Conversion)
- WebCodecs outputs GPU-backed `VideoFrame` handles that can be sampled directly by WebGPU via `device.importExternalTexture()`.
- **Zero Format Conversion & Zero CPU Readback**: Never read pixels back into CPU memory (`ctx.getImageData()` or `frame.copyTo()`) during video processing. All filter passes and compositing must execute entirely in GPU VRAM via WGSL shaders.
- **Zero VRAM Leak**: Every `VideoFrame` created by `VideoDecoder` or synthetic generators MUST be explicitly closed using `.close()` synchronously upon processing completion or channel replacement.

---

## 4. Desktop & Windows Service Radiating Constraints
- Desktop SDK (`crates/native`) exposes clean C-ABI / FFI bindings and integrates native OS hardware encoders (NVIDIA NVENC, Intel QuickSync, Apple VideoToolbox, Microsoft DXVA/D3D11VA).
- Windows Service (`apps/windows-service`) operates as an independent daemon service with robust crash recovery, heartbeat monitoring, and IPC communication.

---

## 5. FastStart Progressive Streaming Invariant
- All output MP4 containers generated by the engine MUST place `moov` BEFORE `mdat` (`faststart`).
- This guarantees zero-buffering instant web playback and HTTP Range request streaming.

---

## 6. Industrial-Grade "Three-Zeros" Verification Invariant
- **Zero Panic**: Pure Rust parser must handle all corrupted bitstreams, malformed SPS/PPS, and truncated NALs without `panic!`.
- **Zero VRAM Leak**: 1,000 continuous frames of decoding, WebGPU shader filtering, or encoding must have net VRAM growth < 5MB and zero unclosed `VideoFrame` handles.
- **Zero Desync Drift**: Audio/Video playback and transcoding must maintain hardware clock synchronization within `|diff| < 40ms`.

---

## 7. Git Hygiene & Clean Commit Invariant
- `.gitignore` strictly guards against committing build targets (`target/`, `node_modules/`, `dist/`), native binaries (`*.dll`, `*.exe`, `*.so`), temporary video/dump clips (`*.mp4`, `*.flv`, `*.raw`), and ephemeral logs (`playwright-report/`, `test-results/`).
- Every commit must be atomic, build cleanly across all packages, and maintain 100% test pass rate.
