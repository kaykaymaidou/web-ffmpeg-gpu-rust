# Web-FFmpeg-GPU Architecture & Engineering Invariants

This project develops a high-performance web multimedia engine powered by **pure Rust WASM** and accelerated by **WebCodecs (GPU hardware decode/encode)** and **WebGPU (WGSL shader filters/composition)**.

## 1. Zero VRAM Leak Invariant
- Every `VideoFrame` created by `VideoDecoder` or `new VideoFrame()` MUST be explicitly closed using `.close()` as soon as processing completes or after feeding to `VideoEncoder`.
- Never hold `VideoFrame` instances indefinitely in arrays or event closures.
- GPU textures created during filtering must be destroyed (`texture.destroy()`) when no longer needed.

## 2. Pure Rust Demuxing & Muxing Invariant
- Parsing of container formats (MP4, MKV, WebM, FLV, TS) and bitstreams (H.264 SPS/PPS/NAL, H.265 VPS/SPS/PPS, AAC ADTS) MUST be written in **pure Rust** (`crates/core`).
- The TypeScript SDK (`packages/core`) is only an orchestration bridge for WebCodecs, WebGPU, and Worker threads. No heavy container/bitstream manipulation should live in TS.

## 3. FastStart Progressive Streaming Invariant
- All output MP4 containers generated by the engine MUST place `moov` BEFORE `mdat` (`faststart`).
- This guarantees zero-buffering instant web playback when streamed over HTTP Range requests.

## 4. RFC-First & Case-Driven Development (Grill-with-Docs)
- Do NOT jump into massive feature implementations without an aligned RFC under `docs/rfcs/`.
- Every feature must be validated against real-world sample cases (B-frames, variable framerates, rotated videos, audio sync).
- Visual telemetry and playground verification (`apps/playground`) must accompany all major releases.
